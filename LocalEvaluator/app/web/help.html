Local Evaluator

Drafts a document-based bid evaluation inside Excel using a model that runs on this computer. Nothing is sent to the internet: the engine listens on 127.0.0.1 only and calls only the local Ollama service.

Getting the pane into a workbook

Excel shows a locally installed add-in only in workbooks that carry a reference to it. Attach it once per evaluation workbook:

  • Close the workbook, then double-click C:\LocalEvaluator\Attach to workbook.cmd and choose it (or drag the workbook onto that file). It opens with the pane on the right.
  • Or open C:\LocalEvaluator\Open Local Evaluator.xlsx and use Attach to a workbook in its pane.

From then on that workbook opens with its own pane every time. A backup copy of the workbook is kept the first time. Only a small reference is added to the file; no sheet is changed. While any workbook with the pane is open, the Local Evaluator button is also at the far right of the Home tab of every workbook.

Steps

  1. Criteria. Open the evaluation sheet. The pane recognises two layouts by itself:
    • One block per bidder (forms such as Administrasi or Form 11A): the criteria table is repeated down the sheet under each "Name of Bidder / Proposer" row.
    • One table: a single criteria table with a "No." and a "Requirement" column. You can also create one from a Word or Excel file, or from a pasted table.
    "Doc Required" and any threshold columns are read when present. Each procurement package can have its own sheets.
  2. Bidders. For a block-per-bidder sheet, click Add AI Evaluation columns once; the bidders are taken from the sheet. For a one-table sheet, add each bidder by name. Then give each bidder a documents folder (PDF, Word, Excel, images, text). Find folders automatically matches bidder names to the sub-folders of a folder you choose. Folders are remembered for the workbook, across its sheets.
    More bidders than the form has room for: on a block-per-bidder workbook, Add a bidder creates a new block on every bidder sheet and a new row on the summary sheet the names come from. It copies the first block, empties what evaluators typed for the first bidder, and rewires the formulas to the new block. Existing rows are not changed, and a copy of the workbook as it was is saved under C:\LocalEvaluator\data\backups. Sheets with a fixed grid of bidder slots (such as scoring forms) are not extended; the pane names them.
  3. Evaluate. One bidder or all. The engine reads the folder (scanned pages are recognised with the Windows text recogniser), finds the pages that relate to each requirement, and asks the model for a finding. The sheet fills in row by row; you can keep working in Excel.

What it writes

  • Three columns to the right of your table: REMARKS, NOTES and ATTACHED DOCUMENT, each marked "(AI Evaluation)". Nothing else is ever written; your own Document Reference, Determination and Remark columns are never touched, so summary sheets that read them are unaffected.
  • Verdict: in the sheet's own words, taken from the dropdown of your verdict column (for example Qualified / Not Qualified / Clarify To Bidder), otherwise Meet / Not Meet / Clarification Required.
  • Note: plain English in black, then "ID:" and the Bahasa Indonesia translation in blue.
  • Attached document: a numbered list of the files and pages relied on. A cell with one file opens that file when clicked.

Checks done by fixed rules, not by the model

  • The verdict follows a fixed decision table from the model's finding.
  • A "met" finding must cite a page that was actually read; otherwise it becomes a clarification.
  • A document whose printed validity ended before today is treated as expired.
  • A document in another company's name is not accepted without clarification (except where the requirement is about the manufacturer).
  • A figure below the stated minimum is flagged for a hand check.
  • "Nothing found" becomes a clarification when some files could not be read.

Limits to keep in mind

  • The result is a draft from a small local model. Check every row against the documents before the Committee relies on it.
  • Each requirement takes a few minutes on this laptop. Close other programs to free memory.
  • Sums, averages and date arithmetic (turnover, years of experience) are the model's weakest area; verify those rows by hand.
  • Evaluating again clears Excel's Undo history for the sheet. The previous AI columns are saved under C:\LocalEvaluator\data\runs.

Keeping it offline

  • Keep bid documents and workbooks on a local drive, not in a cloud-synced folder.
  • For a hard guarantee, switch on airplane mode while evaluating, or add Windows Firewall outbound rules for ollama.exe and Python.
